Creator roadmap — manual steps + progress tracking
====================================================

Purpose
-------
This file lists what YOU (the project owner) must do outside the repo:
Supabase/Vercel dashboards, secrets, and final approval. The coding agent
can mark "agent verified" items after checking the codebase or a successful
local/build check — but only YOU can complete dashboard/account steps.

How to use checkboxes (creator + agent)
-----------------------------------------
- [ ] = not done   |   [x] = done
- Creator-only lines (Sections A–F, except "Agent can verify" rows):
    Mark [x] ONLY after you completed the step in the real dashboard / account.
- "Agent can verify" rows:
    Agent may mark [x] after confirming the claim in the repo or a clean build,
    NEVER as a substitute for a creator step.
- Append one line to "Progress log" with date | who | what was done.
- Optional inline date next to a checkbox, e.g. [x] 2026-05-02

SECTION A — Accounts & projects (creator only)
================================================================================

[ ] A1. Create or open Supabase project (production).
[ ] A2. Create or open Vercel project linked to this repo (or import Git repo).
[x] A3. Register Mapbox account and create a public access token (`pk.…`) for the map
        (see VITE_MAPBOX_TOKEN in specs/08-deployment.md).
        Mapbox naming (recommended): in the Mapbox dashboard, rename the token to something
        you will recognize later, e.g. `opensos-dev-unrestricted` while developing without
        URL restrictions. Before production, either (a) add URL restrictions to that token
        for your real origins (https://<your-vercel-app>.vercel.app/*, custom domain, and
        optionally http://localhost:<port>/* for local dev), or (b) create a second token
        named e.g. `opensos-prod-restricted` with URL allowlist only, put it in Vercel env,
        and keep the dev token for local `.env` only.
[ ] A4. (Before first prod deploy) Harden Mapbox token: URL restrictions on the token used
        in Vercel (see A3). Do not use secret scopes on any token that lives in VITE_*.

Agent can verify (after you say it is done):
[x] AV-A1. Agent confirms Supabase URL + anon key are NOT committed; only .env.local / Vercel.
